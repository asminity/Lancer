# Arkiv Database Schemas & Storage Architecture

This document defines the schema specification for **AUTONEX** on the **Arkiv Rabdi DB-Chain Testnet** (`Chain ID: 7794095`).

All entities are created, queried, and verified using the official `@arkiv-network/sdk`.

---

## 1. Schema Overview

AUTONEX uses four specialized schemas designed to balance verifiable decentralization, query performance, and storage costs:

| Schema Name | Primary Purpose | Retention (TTL) | Ownership | Max Size |
|---|---|---|---|---|
| `autonex.run` | Execution metadata, DAG snapshot, lifecycle state | 90 Days | User Wallet | ~2 KiB |
| `autonex.deliverable` | Full codebase bundle, test results, markdown report | 90 Days | User Wallet | ~128 KiB |
| `autonex.swarm_round` | Deliberation rounds, Borda tally, quorum proofs | 90 Days | User Wallet | ~16 KiB |
| `autonex.audit_log` | Immutable trace of human permissions granted to agents | 90 Days | User Wallet | ~1 KiB |

## 2. Schema Definitions

### 2.1. `autonex.run`
Represents an autonomous software engineering execution session (either in Deskmates 3D Office or Swarm Hall).

```typescript
export const RunSchema = defineSchema({
  name: 'autonex.run',
  columns: {
    run_id:       { type: 'str',   isIndexed: true  }, // Unique UUID / run identifier
    owner:        { type: 'addr',  isIndexed: true  }, // Connected user wallet address
    task_class:   { type: 'str',   isIndexed: true  }, // full_build | quick_sprint | bug_fix | triage
    mode:         { type: 'str',   isIndexed: true  }, // office | swarm
    status:       { type: 'str',   isIndexed: true  }, // IN_PROGRESS | SUCCESS | HALTED
    created_at:   { type: 'u64',   isIndexed: true  }, // Unix timestamp in seconds
    goal_summary: { type: 'str',   isIndexed: false }, // Sliced task description (max 120 chars)
    duration_s:   { type: 'u64',   isIndexed: false }, // Execution wall clock duration
    total_tokens: { type: 'u64',   isIndexed: false }, // Total LLM tokens consumed
    dag_json:     { type: 'bytes', isIndexed: false }, // Serialized execution graph (non-indexed)
  },
});
```

- **Indexed Fields:** `run_id`, `owner`, `task_class`, `mode`, `status`, `created_at`
- **Query Patterns:**
  - Query all runs by user: `and(eq('arkiv.schema', 'autonex.run'), eq('owner', addr(userAddress)))`
  - Query public runs: `eq('arkiv.schema', 'autonex.run')`
  - Filter by status: `and(eq('arkiv.schema', 'autonex.run'), eq('status', 'SUCCESS'))`

### 2.2. `autonex.deliverable`
Stores the complete multi-file project source code, automated test verification proofs, and human-readable reports generated by autonomous agents.

```typescript
export const DeliverableSchema = defineSchema({
  name: 'autonex.deliverable',
  columns: {
    run_id:        { type: 'str',   isIndexed: true  }, // References parent autonex.run
    project_slug:  { type: 'str',   isIndexed: true  }, // Clean URL slug for project
    l2_tests_pass: { type: 'bool',  isIndexed: true  }, // Whether L2 tests passed (vitest/pytest)
    l3_score:      { type: 'dec',   isIndexed: true  }, // Quality score (0.00 to 100.00)
    file_count:    { type: 'u64',   isIndexed: false }, // Total files in deliverable
    total_lines:   { type: 'u64',   isIndexed: false }, // Total code lines
    bundle_bytes:  { type: 'bytes', isIndexed: false }, // UTF-8 JSON dictionary of { path: content }
    report_md:     { type: 'bytes', isIndexed: false }, // Final markdown report
  },
});
```

- **Indexed Fields:** `run_id`, `project_slug`, `l2_tests_pass`, `l3_score`
- **Non-Indexed Payloads:** `bundle_bytes` and `report_md` are stored in raw byte columns. This avoids unnecessary index overhead while allowing full multi-file codebases to be unpacked directly into browser or local disk.

### 2.3. `autonex.swarm_round`
Captures cryptographic proofs of multi-agent deliberation rounds, weighted Borda ballots, and semantic consensus clustering.

```typescript
export const SwarmRoundSchema = defineSchema({
  name: 'autonex.swarm_round',
  columns: {
    run_id:         { type: 'str',   isIndexed: true  }, // References parent run
    round:          { type: 'u64',   isIndexed: true  }, // Deliberation round index (1 to 6)
    swarm_size:     { type: 'u64',   isIndexed: false }, // 10, 20, 30, 40, or 50 agents
    agreement:      { type: 'dec',   isIndexed: true  }, // Consensus quorum percentage (e.g. 92.40)
    moderator:      { type: 'str',   isIndexed: false }, // Lead persona (e.g. "Diya")
    clusters_cnt:   { type: 'u64',   isIndexed: false }, // Semantic idea clusters count
    ballots_cnt:    { type: 'u64',   isIndexed: false }, // Total agent ballots cast
    veto_triggered: { type: 'bool',  isIndexed: false }, // True if risk analyst exercised veto
    consensus_json: { type: 'bytes', isIndexed: false }, // Serialized voting tally & critique trees
  },
});
```

- **Indexed Fields:** `run_id`, `round`, `agreement`
- **Query Patterns:**
  - Retrieve quorum proof: `and(eq('arkiv.schema', 'autonex.swarm_round'), eq('run_id', runId))`

### 2.4. `autonex.audit_log`
Provides an immutable on-chain record of human approvals granted to autonomous agents for sensitive actions (`file.write`, `shell.exec`, `file.read`).

```typescript
export const AuditLogSchema = defineSchema({
  name: 'autonex.audit_log',
  columns: {
    run_id:       { type: 'str',   isIndexed: true  }, // Associated run
    action:       { type: 'str',   isIndexed: true  }, // file.read | file.write | shell.exec
    decision:     { type: 'str',   isIndexed: false }, // once | always | reject
    agent_id:     { type: 'str',   isIndexed: false }, // Requesting worker agent
    operator:     { type: 'addr',  isIndexed: true  }, // Approving user wallet address
    timestamp:    { type: 'u64',   isIndexed: false }, // Approval timestamp
    resource:     { type: 'str',   isIndexed: false }, // File path or shell command
    diff_preview: { type: 'bytes', isIndexed: false }, // Code diff or terminal command preview
  },
});
```

- **Indexed Fields:** `run_id`, `action`, `operator`

## 3. Ownership & Authorization Model

1. **User-Owned Architecture:**
   - Every entity write (`createEntity`, `patchEntity`, `extendEntity`, `deleteEntity`) is authorized directly by the user's connected wallet (e.g. MetaMask).
   - In `RunSchema`, the `owner` column is set to `addr(userAddress)` with Viem checksum validation (`getAddress()`).
   - The user's wallet signs the transaction and pays the native `tGLM` gas fee on the Rabdi DB-Chain.
   - There are **no backend signers**, no centralized custody, and no hardcoded private keys.
2. **Zero-Gas Public Read Permissions:**
   - Read operations (`arkivPublicClient.query()`, `arkivPublicClient.getEntity()`) are open and permissionless.
   - Anyone can inspect project runs, verify multi-agent consensus proofs, and download the full generated source code from `bundle_bytes` without connecting a wallet or paying gas.
3. **Modification & Pruning Permissions:**
   - Only the wallet matching the on-chain entity owner can call `extendEntity` (to renew storage TTL) or `deleteEntity` (to prune state from Rabdi DB-Chain).

---

## 4. Expiration Policy & Cost Optimization

1. **Retention Periods:**
   - Default expiration is set to **90 Days** (`ExpirationTime.fromDays(90)`).
   - 90 days provides ample persistence for hackathon evaluation, peer review, and continuous testing while avoiding perpetual state bloating on testnet nodes.
2. **On-Demand Extension:**
   - Projects can be preserved indefinitely by calling `extendArkivEntity(walletClient, entityKey, 90)` (+90 days per call).
3. **Storage Cost Optimizations:**
   - Heavy payloads (`bundle_bytes`, `dag_json`, `consensus_json`) are stored as **non-indexed `bytes`**. This eliminates the computational overhead and indexing costs that would occur if large strings were indexed.
   - Strings are bounded: goal summaries are capped at 120 bytes, task classes at 30 bytes, and schema names follow strict naming conventions.
   - Code files are compressed into a unified JSON dictionary before encoding into `Uint8Array`, strictly respecting the 128 KiB `MAX_ENTITY_BYTES` ceiling.
